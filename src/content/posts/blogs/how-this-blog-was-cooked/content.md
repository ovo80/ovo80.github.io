## 前言

想搭个人博客这个念头，其实已经搁置了好几个月。

每次都有充分的理由推迟：学业太忙、技术栈没选好、现有主题不合意、想自己从头写一个……结果就是，域名买了三四个，服务器续费了好几个月，博客却始终没有落地。

这次能够完成，主要靠两件事：**AI 辅助开发**和**现成的开源主题**。

## 技术选型：为什么是 Astro + Fuwari

最早考虑过 WordPress，但一想到要维护 PHP 环境和数据库，就打消了念头。后来在 Vercel 上试用过几个 Next.js 博客模板，总觉得过于复杂——对于以文字为主的博客，没有必要加载几百 KB 的 JavaScript。

最终选择了 **Astro**，理由有三：

1. **默认输出纯 HTML，几乎不加载 JavaScript**。这对以文字内容为主的博客来说非常合适。
2. **支持在同一项目中混用 React、Vue、Svelte 组件**。虽然目前尚未用到，但保留了扩展空间。
3. **社区模板质量高**。

模板选用了 **Fuwari**，原因很简单：它是翻阅 GitHub 之后，第一眼就觉得合适的。常用功能一应俱全：暗色模式、全文搜索、代码高亮、图片预览、RSS 和 Sitemap 自动生成。而且代码结构清晰，方便后续自行修改。

## 搭建过程：AI 的辅助作用

从克隆仓库到完成这篇文章，**我几乎没有手写过一行前端代码**。

整体流程如下：

1. 克隆 Fuwari 仓库，执行 `pnpm install` 安装依赖。
2. 修改 `src/config.ts` 中的站点标题、副标题和作者信息。
3. 对文章 Frontmatter 格式不熟悉？直接让 AI 生成一份带注释的模板。

过程中我做的唯一体力活，就是在终端里执行 `pnpm dev` 和 `git push`。

这种感觉和以前很不一样——过去搭博客，大部分时间都花在调整样式、修复间距、对齐像素上，真正想写内容的心情早就消磨殆尽。现在 AI 处理了这些繁琐的环节，我只需要专注于标题和正文。

## 部署：Cloudflare Pages

GitHub Pages 和 Vercel 都用过，这次选择了 **Cloudflare Pages**，理由如下：

- 与 GitHub 的集成体验和 Vercel 一样顺畅，`git push` 后自动构建部署。
- 免费计划自带 DDoS 防护和全球 CDN，对个人博客来说绰绰有余。
- 顺带把域名 DNS 也迁到了 Cloudflare，实现统一管理。

部署过程出乎意料地简单：在 Cloudflare 后台授权 GitHub、选择仓库，平台自动识别 Astro 框架，并填好构建命令和输出目录。点击保存并部署，稍等片刻即上线。

## 一些感想

博客说到底，就是一个表达和记录的地方。

以前总想着等自己"技术够强""内容储备够了"再开始，结果一直停留在准备阶段。

这次想明白了：**先开始写，再逐步完善。**

博客已经上线，内容会陆续更新。下一篇会写什么，我自己也不确定，但应该不会太久。
